2026 年 AI Agent 市场快速升温，产品层出不穷：DeepSeek Harness、腾讯 Workbody、Hermes Agent、OpenAI Codex。表面上看，它们都属于"能自主完成任务的 AI"，容易让人以为差异只在模型能力的高低。实际拆开会发现，四款产品走的是四条不同的发展路线，分别面向不同的用户群体，解答不同的问题。

本文先逐一拆解四条产品化路线的定位、优势与代价，再分析路线背后的商业化逻辑与路径，最后对行业走向做几点展望。

## 四条产品化路线

### DeepSeek Harness：面向开发者的运行底座

Harness 一词原指"马具、缰绳"，在这里指大模型之外的一整套运行系统：工具调用、文件访问、记忆存储、任务调度和工作环境。大模型提供智能，Harness 决定这些智能能否转化为稳定的工作执行。

DeepSeek Harness 的核心理念是"一切皆插件"：大模型可以替换，工具可以替换，记忆系统、任务调度方式乃至用户界面都是可插拔的模块，开发团队通过配置组合能力，而不必修改框架代码。它的优势集中在三方面。开放性与可组合性强，企业可以同时接入多家模型，按任务复杂度和数据敏感程度分配不同的模型，敏感数据可以交给本地部署的模型处理。运行过程全程留痕，模型每一步的输入、指令、工具调用和子任务派发都被记录，任务可以恢复、搜索、分叉和重放，为调试、评估和审计提供依据。它还提供标准、代码、最小、Creator 四种工作模式，分别覆盖常规任务、复杂编排、能力测试与插件开发。

它的局限同样明确：目前处于开发者预览阶段，更接近面向专业开发者的基础设施而非终端产品，模型选型、工具接入、权限配置、数据存储都由使用方自行负责。它适合有开发能力、希望构建可控可扩展 Agent 系统的企业与团队。

### 腾讯 Workbody：开箱即用的办公成品

如果说 Harness 提供给开发者的是可组装的底盘，Workbody 交付的则是装配完成的整车。它的目标用户是普通职场人，交互方式是自然语言：用户描述目标，系统自动理解、拆解任务，调度不同领域的"专家"并行处理，最终交付可检查、可修改的成果，覆盖资料搜集、市场调研、表格分析、内容撰写、文件整理等办公场景。

它的优势集中在三点。使用门槛低，不要求编程或配置能力，安装即可使用。对中文办公场景和国内生态的适配深入，覆盖 Windows 与 macOS，打通主流即时通讯工具和微信小程序，产品设计贴近国内用户的办公习惯。它还将多智能体协作封装为"专家团队"的概念，用户不必理解角色编排与任务调度，显著降低了认知成本。

代价来自成品化本身：用户对底层运行细节的掌控有限，透明度、可定制程度和模型选择自由度都不及框架类产品；面对特别复杂的代码仓库和严格的软件测试任务，它也未必优于专业编码 Agent。它适合希望快速提升办公效率、不愿意投入部署配置成本的办公人群。

### Hermes Agent：随使用积累价值的长期员工

Hermes Agent 由 Nouns Research 团队开发，出发点与前两者不同：一个有价值的智能体，不应每次对话都从零开始，而应在长期使用中形成记忆、掌握工作习惯，并将成功经验沉淀为可复用的技能。

支撑这一目标的是两套系统：长期记忆保存用户偏好、项目背景和历史经验；技能系统把多步骤流程固化为可一键调用的 Skill，遇到同类任务直接复用既有方法。模型层保持开放，可接入 OpenAI、Claude、Gemini、DeepSeek、千问等云端模型以及本地模型——记忆与技能归属于 Agent 本身而非某个大模型，更换模型不会丢失已积累的工作方法。它还支持长期在线运行，可部署在自有设备或云端，通过飞书、企业微信、Telegram 等渠道交互，并内置定时任务与子 Agent 能力，适合周期性与长周期自动化场景。

关于它的"自进化"需要一点澄清：进化并不发生在大模型权重层面，而是在记忆、技能和系统提示层迭代。这带来一个必须正视的风险——错误经验一旦被写入，可能在后续任务中被反复调用。因此产品为记忆和技能的写入设置了人工审批机制：Agent 提出修改建议，由人审核差异后批准生效。它适合需要长期在线、逐步适配个人工作方式的用户。

### OpenAI Codex：强调验证的专业执行体系

Codex 已从早期的编码助手，发展为桌面端、命令行、IDE 插件与云端环境组成的完整体系，核心始终围绕代码、项目与工程执行；通用办公能力更多放在 ChatGPT Work 中，两者的能力正在逐步共享。

它的第一个特点是完成并验证，而不止于给出建议：读取整个项目、修改多个文件、执行命令、运行测试、根据报错继续修复，最终交付包含修改摘要、文件差异对比和测试结果的完整成果。第二个特点是工程环境完整：本地端可直接使用已安装的编译器、测试工具与项目依赖；云端为不同任务建立隔离环境，支持多任务并行，结果经审查后可提交至代码仓库。第三个特点是权限与安全边界成熟：通过沙箱限制文件与网络访问，高风险操作需请求批准——这类设计虽然显得保守，但对能够真实修改文件、运行程序的智能体而言，约束本身就是可靠性的组成部分。

局限在于它围绕 OpenAI 自家模型与 ChatGPT 服务运行，模型选择自由度低于前三条路线；产品取向上也偏保守，不将自动修改长期规则作为核心能力。它适合复杂代码任务、工具执行以及需要严格验证的专业工作。

四条路线的取舍可以概括为三组问题：需要成品工具，还是可开发的框架；看重即时效率，还是长期成长；是否需要掌握模型、数据与运行环境的控制权。

| 路线 | 核心追求 | 主要代价 | 适合人群 | 商业模式 |
|------|---------|---------|---------|---------|
| DeepSeek Harness | 架构自由 | 配置责任全在使用方，仍处预览阶段 | 自建 Agent 系统的开发团队 | 基础设施授权与云服务 |
| Workbody | 使用便利 | 底层控制权有限 | 追求即时效率的办公人群 | 订阅制 |
| Hermes Agent | 长期成长 | 错误经验需人工审批把关 | 长期在线的个人 AI 员工 | 订阅与增值服务 |
| OpenAI Codex | 可靠交付 | 绑定 OpenAI 模型与服务 | 复杂、需严格验证的专业任务 | 按任务与结果计费 |

## 商业化：逻辑与路径

四条路线并存的背后，是一个正在发生的价值转移：模型能力逐步趋同之后，竞争重心从"谁的模型更聪明"转向"谁的系统能稳定交付工作"。

四条路线的收入结构并不相同。底座类产品的商业模式接近基础设施，通过能力授权与云服务收费，价值随其上运行的 Agent 规模同步增长。通用成品延续订阅制，收入与用户规模挂钩，但这类产品提供的能力距离模型层最近，随着模型迭代，部分能力会被基础模型厂商直接吸收，因此必须依靠生态入口与场景粘性维持差异化。长期 Agent 的价值来自使用时长的积累，记忆与技能既构成产品体验，也构成续费与增值服务的基础，用户的迁移成本随积累加深而持续提高。专业执行类产品则在走向按任务、按结果计费，这是当前最值得关注的定价变化。

按结果计费的经济学基础，是 AI 服务的定价参照系从软件席位转向岗位人力成本。以客服场景为例，Intercom Fin 按问题解决计费，每次 0.99 美元，高价值的线索筛选单列为每条 9.99 美元；同类产品 Fini 已将单价压至 0.69 美元，Sierra、Ada 采用相同模式。对照来看，人力坐席摊到每次会话的成本在数美元量级，而 Agent 的成本端是推理算力，仅几美分。定价参照人力成本，成本参照算力支出，两者的差额构成这门生意的基本毛利空间。价格竞争如此快地展开，也说明"结果"本身正在商品化；能够支撑溢价的，是结果的质量承诺与责任承担——服务水平协议、错误赔付与审计记录。

商业化逻辑的另一条主线，是模型与场景上下文的分离。大模型可以通过 API 租用，场景上下文却无法租用：业务流程、数据接口、权限体系、历史决策与错误案例，都需要在实际工作中逐项沉淀。Harvey 在法律领域的增长印证了这一点：2026 年 3 月融资时年经常性收入约 1.9 亿美元，到 7 月已被第三方机构估算至 3.5 亿美元。律所持续付费购买的不是模型调用，而是法律工作流、语料积累、合规边界与责任保障。这类沉淀下来的上下文，构成企业难以迁移的资产。

路径上，四条路线各有侧重：通用成品依靠生态入口扩大用户基数；底座产品争取成为开发者标准；长期 Agent 将记忆与技能沉淀为资产；专业 Agent 的可行公式是"一个高价值岗位、一套高频流程、一套专有数据、一组企业系统、一个可量化的结果"，从法律、客服、编码等岗位依次推进。四条路线共享同一个推进方式：先在低风险、高频次场景中验证任务成功率与成本结构，待治理与评估体系建立——任务成功率、人工介入率、单任务成本、回滚率等指标可供审计——再逐步授权至付款、数据库写入等高价值、高风险操作。信任边界的扩展速度，决定商业化能走多远。

## 收尾与展望

三点行业判断。

其一，Agent 的竞争不会停留在模型层面。模型决定智能上限，决定能否稳定落地的是运行底座：工具调用、记忆存储、任务调度、错误恢复与运行透明度。

其二，自进化不能脱离评估体系。完整的执行记录、客观的测试数据、效果比较机制、人工审批与错误回滚，缺少任何一项，自我改进都可能退化为对错误的固化。

其三，最好的 Agent 未必是最自主的 Agent。风险越高的操作，越需要保留人工判断节点；成熟的系统不是取消人的判断，而是将人的判断集中到最关键的环节。

展望未来几年，大概率不会出现一款超级 Agent 覆盖所有场景；更可能的形态是四条路线分工协同——通用办公 Agent、专业工程 Agent、长期个人 Agent 与企业自建底座，共同组成完整的工作系统。企业软件架构将随之分层：人在最上层负责目标、判断、审批与异常处理；各岗位 Agent 构成劳动力层；控制面统一管理权限、工具与评估；模型、记忆与技能成为可替换的底座；ERP、CRM、OA 继续承担记录与执行。

最后用业内流传的一个判断适合作为收尾：第一轮 AI 竞争比拼最强的大脑，第二轮比拼最好的 Agent，第三轮比拼的将是谁拥有最多可执行的工作。模型仍会继续进步，但价值正在从模型层迁出，向工作流、运行底座与组织记忆沉淀。
